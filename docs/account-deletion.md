# Account deletion

D2a establishes a durable **pending** access fence. It does not complete physical erasure. The self-delete settings button stays disabled until D2b's cleanup, cancellation and restore-suppression acceptance is complete. Admin `users.remove` follows the same request path and returns pending instead of cascading the account.

The self request is cookie-only, protected by the existing second-factor policy and its own fail-closed rate budget. It accepts exactly the typed `DELETE` confirmation and derives the account from the session. A live, non-impersonated browser session must carry server-owned `authenticatedAt` proof from primary password or identity-provider authentication within five minutes; its creation time is not proof. Factor enrollment and cookie rotations preserve the parent proof, and sign-in code completion preserves the original password proof time. Password and SSO users both sign in again when stale; missing proof requires a new sign-in. Every administrator must first transfer their authority. The shared last-active-admin guard also protects admin-initiated removal and excludes deletion-pending accounts from usable-admin counts.

The request takes password-write → CLI-credential → set-password-link → hosted-admission locks before opening its Serializable admin-removal snapshot. It records `deletionRequestedAt` and `deletionState=pending`, stops active matches as `owner-delete`, clears human turns, revokes sessions/API keys/device approvals/runner authority, and removes the sealed OpenRouter connection. The official settlement trigger preserves all accepted official starts. Failed transactions roll back acceptance; retries read the original timestamp and cleanup phase without resetting progress. A successful response states `complete:false`; session revocation then signs the requester out. There is no unauthenticated status receipt or external email link.

Every later credential mint, callback, hosted admission, move and actual provider request must recheck active account authority under its relevant lock. Runner transport checks the authoritative `isOwnerActive(userId)` on connect, messages and heartbeat. A key request admitted before the fence may remain in flight: D2b must stop/confirm all such leases and sockets before claiming completion. Removing a locally stored key does not revoke that key at OpenRouter; the user must also revoke it at OpenRouter's key settings if desired.

Published rows are hidden while their owner is pending. The retained replay scrubber processes at most 50 rows per keyset batch and detaches ownership only with a sanitized archive. It rotates neutral slugs and public IDs, drops old identity-bearing URLs, title and names, raw replies, remarks, comments, tool text and archive IDs. It retains legal moves/board, trusted catalog model identifiers, prompt/settings and numerical results. Null-owner public reads sanitize again; exported JSON/PNG/MP4 use the same projection. Sanitization never changes publication/moderation state. Private replay removal is explicit cleanup; nullable ownership uses `SetNull` rather than a cascade. Minimal owner-independent official commitments survive both private and published cleanup.

## Cleanup inventory for D2b and export inventory for D2c

| Storage | D2a fence | D2b physical cleanup / D2c export constraint |
| --- | --- | --- |
| User lifecycle | Indexed pending state, timestamp, retry count/cursor | Resume safely after any failure; do not reset tombstone or report completion early. Delete User only after resource termination and scrub/private cleanup |
| Session, Account, TwoFactor | Sessions revoked, account authority refused | Remove rows by User FK, including SSO tokens/password hash/2FA secret; export only safe account metadata |
| ApiKey, DeviceCode, RunnerMachine | API keys/device codes removed; runners revoked with generation bump and transactional ID-only notification | Delete rows after live runner termination; never export credential digests or secrets |
| RunnerClaim | Original User/session authority rechecked under the CLI-credential lock for browser claim and approved poll/exchange, including credential recovery; pending owners cannot bind or mint despite a surviving session | User, approving Session and linked RunnerMachine FKs cascade the claim/recovery row. Remove owner-bound rows during cleanup; anonymous unbound claims carry no owner identity and expire after 10 minutes. All claim states share a 1,000-row cap with expiry cleanup in batches of 100. D2c never exports URL tokens, CLI proofs, purpose-bound digests or recoverable runner credentials |
| OpenRouterConnection | Sealed connection removed and new saves refused under credential lock | Confirm in-flight key-use leases stopped. D2c exports connection metadata only, never key/ciphertext/nonce |
| ChessMatch | Queued/running work stopped with claim fence; pending-owner public reads refused | Keyset sanitize and detach published rows; keep moderation state. Delete private rows. D2c JSON/PGN export includes user's private and published games before deletion |
| ChessOfficialEntry, ChessCreation | No account identity stored in ledger; starts/settlement retained | Never delete official commitments. Detach match relation as transcripts disappear; no reverse owner join. Creation receipt contains purpose-bound digest, no raw owner/config/title |
| Verification (non-FK) | Account/mint/reset/SSO authority refused; reset/two-factor proofs revoked by shared revoker | Remove exact per-user reset identifiers/values, mailed-reset email JSON, verification emails, pending 2FA/SSO proofs; inventory current formats again before cleanup. Do not scan all values or unrelated users |
| Redis OAuth state | Short expiry and hard pending-owner callback/save refusal | Remove indexed per-user state if available; otherwise let bounded TTL expire behind durable refusal. Never scan all Redis keys |
| Redis connection/runner/key-use leases | Durable account/credential checks and invalidation | Cancel/abort and await bounded proof across replicas; uncertainty stays pending; missed notification never restores authority |
| Bull jobs, results, transient worker archives | DB status/runToken prevents future writes/spend | Remove deterministic jobs/results via bounded owner registry; payloads carry IDs, never provider keys; late worker persistence stays fenced |
| Browser query/SSR/service-worker caches | Identity/session boundary clears private client state; public reads hide pending owner | Visibility refresh removes retained stale transcript within its documented bound. Already downloaded files/runner disks belong to the user and cannot be erased remotely |
| Reports/moderation (D3) | No transcript copied by default | Preserve hiding; scrub reporter identity/free text or only retain explicitly approved minimal moderation evidence. D2c exports own filed reports, not others' private reports |
| Operational logs/mail | No new credential/body logging | Respect documented retention; no claim to instant erasure of prior delivery or remote logs |
| Backups/suppression register | No restore completion claim | Restricted deletion suppression outside restorable snapshots must be reapplied before reopening admission. Daily encrypted off-VPS backups and 30-day expiry are G1 deployment acceptance, not D2a proof. Retain suppression through the last restorable backup |

D2c is a separate signed-in, rate-limited, step-up-protected streamed JSON/PGN download. It must include account metadata, private and published games, safe OpenRouter metadata, runner machines and reports filed. It must clean up mailed-reset Verification JSON during later deletion and never export keys or authentication proofs. No export endpoint or completion UI is enabled by D2a.
